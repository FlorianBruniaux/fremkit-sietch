# Gmail inbox

Proposed original code under the repository MIT license. Requires Fremkit SDK 1 **and** the core Google OAuth integration, Gmail provider payload contract v1, multi-account `connections` settings and the `connectionService` account guard. SDK 1 by itself does not establish that these providers are installed. No external assets, direct network requests or credential access.

Install from a development catalogue after reviewing consent. In admin, authorize Google with Gmail metadata access, then select the intended Google accounts in the widget's settings. The manifest declares `connectionType: google`, `connectionService: gmail` and `gmail:*` subscriptions, with no default selected account. Credentials remain in the host SecretStore. Use several accounts in one full tile on a Google page, or set a small row limit for a Home summary.

Displays unread sender, subject, source timestamp and explicit account identity. It does not display snippets, bodies, attachments or credentials. Merges headers newest first with missing dates last, and bounds the full view to 1–30 rows (default eight). Counts remain approximate: the provider's unread estimate is labeled as an estimate, and missing values remain unknown. Loaded-row and provider truncation disclosures do not claim an exact unread total. A successful empty response, a missing response and retained stale headers have different presentation; one failed account does not erase healthy accounts.

Account filters use exact connection IDs. Changing the selected account set or the account filter first clears all snapshots, increments the subscription generation and unsubscribes every old channel. Old callbacks cannot restore removed data, including after the same account is reselected. Account labels on rows never serve as routing keys.

Opening is available only for a fresh loaded message advertising `open.available: true` with no unavailable reason. The widget sends `Fremkit.sendCommand('gmail:' + connectionId, 'open', { connectionId, messageId })`. The core re-fetches that exact message and builds its thread link using the verified Google account's email. Progress and success/failure are shown in a visible status notice. The widget constructs no Gmail URLs and performs no API mark-read, archive, reply or send actions. Opening mail in Gmail itself may mark it as read according to Gmail's normal behavior.

French/English strings, transparent surfaces and host light/dark/accent tokens apply to full and compact layouts. Full filters and controls have at least 56 × 56 px targets, with visible keyboard focus. Compact mode is a read-only summary of at most two accounts, disclosing additional accounts; the host controls its full-tile touch popover and navigation slot. Full account filters are not compact touch controls.

From the registry root, run `pnpm exec vitest run tools/test/google-widgets.test.ts`, then `pnpm test`, `pnpm typecheck`, `pnpm validate`, `pnpm build` and `pnpm check-vendor`. The tests execute the delivered inline script using synthetic provider snapshots. Real account consent, installed-catalogue behavior and XENEON physical touch remain unverified.

# Codex sessions

Requires Fremkit SDK 1 and the opt-in `codex` core provider. Codex must be installed and its account must be configured outside this widget. This package contains original MIT-licensed code and no external assets or credential access.

Displays at most fifty selected stored sessions in compact cards, grouped into collapsible repository sections. When supplied by the core, groups reuse the saved Codex project ID and name, so worktrees remain under their original project and identically named projects stay separate. Unknown project metadata and explicitly projectless sessions are separate groups. Older cores retain directory-label grouping. Counts refer to the loaded session subset; provider pagination remains disclosed. Groups are ordered by their most recently listed session, retaining history order inside each group. Collapse state stays in iframe memory across snapshot updates and project renames, without using localStorage. Collapsing a group closes its agent panel and cannot open a hidden session. Live states, models, thinking effort, durations and subagents come only from the opt-in observations provider; missing or old observations remain unknown. Source labels describe recorded origins. Opens only a fresh, recently updated `navigation: localChat` record with `Fremkit.sendCommand('codex', 'open', { threadId })`. The host validates again. CLI/cmux focus remains unavailable because the core contract provides no proven terminal mapping. Stale, missing or unvalidated navigation is disabled; duplicate titles retain their exact IDs.

Both layouts use host theme tokens, transparent backgrounds and navigation slot alignment. Compact mode is a read-only summary; its full-tile popover is controlled by the host. History row buttons have 56 px minimum touch targets. Loading, unconfigured, unauthorized, unsupported, invalid and offline states are translated into French and English.

Run from the registry root: `pnpm exec vitest run tools/test/codex-widgets.test.ts`. Tests run the delivered widget script with synthetic provider snapshots. Synthetic tests cover repository identity, duplicate labels, collapse state, exact-ID opening and preservation of observed model/agent information. Physical touch remains a separate validation.
